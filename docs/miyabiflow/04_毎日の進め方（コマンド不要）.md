# 04 毎日の進め方（コマンド不要）

この章の通りに進めれば、初心者でも **1周完走**できます。

---

## ステップ0: 今日やることを1行で書く（あなたがやる）
例:
- 「ログイン画面でパスワードを忘れた時にリセットできるようにしたい」
- 「CSVをアップロードしたら件数を表示したい」

---

## ステップ1: Claude Code に “計画を作って” と頼む（あなたは日本語を打つだけ）
Claude Code に次を貼る:

> **お願い**: MiyabiFlow（雅フロー） で進めたいです。私はターミナルでコマンドを打ちません。必要な操作はあなたが行い、許可が必要なら私がクリックします。  
> まず [要求定義] を確認し、**1〜3時間単位**のタスクに分解して **plan** を作ってください。  
> 各タスクには: 受入条件 / テスト（TDD） / 影響範囲 / Done条件（make ci）を付けてください。

Claude Code の出力で確認するポイント:
- タスクが小さく分かれている
- タスクに順番（依存）がある
- テストが含まれている

---

## ステップ2: Claude Code に “作業場所を分けて” と頼む（worktree）
あなたは言うだけ:

> この plan に沿って、タスクごとに [並列作業ツリー]（git worktree）を作成してください。  
> 各 worktree に `TASK.md` を作り、手順とチェックリストを書いてください。

> ここで Claude Code が git コマンドを実行します。あなたは “許可” を押すだけです。

---

## ステップ3: 1つ目のタスクを実装する（TDD）
Claude Code に言う:

> まず最初のタスクを開始してください。  
> **TDDで**進めます。最初に失敗するテスト（Red）を作り、次に最小実装（Green）、最後にリファクタ（Refactor）で仕上げてください。

---

## ステップ4: “合格判定” をして（品質ゲート）
Claude Code に言う:

> `make ci` を実行して、失敗したら原因を説明し、直して、もう一度 `make ci` を通してください。  
> 私はコマンドを打ちません。必要ならあなたが実行し、許可が必要なら私がクリックします。

---

## ステップ5: PRを作る（GitHub、クリック中心）
最初は **GUI** でOKです（GitHub Desktop 推奨）。
- ブランチを publish / push
- GitHub Web で “Compare & pull request” を押す
- PRテンプレに沿って文章を書く（Claude Code に書かせてコピペしてOK）

Claude Code への依頼文（PR本文）:
> PR本文を初心者向けに書いてください（何を/なぜ/どう検証）。チェックリスト形式で。

---

## ステップ6: Codex にレビューさせる（コマンド不要）
GitHub の PR コメントで:
- `@codex review`

Codex がレビューを返します（しばらく待つ場合があります）。

---

## ステップ7: 指摘を直す（Claude Codeに任せる）
Claude Code に貼る:

> PRに `@codex review` の指摘が来ました。  
> 指摘をP0/P1/P2に分類し、P0/P1を優先して修正してください。修正後に `make ci` を通してください。

---

## ステップ8: 人間が承認してマージ（あなたがやる）
- CIが緑
- レビューOK
- 自分が納得

→ Approve → merge

---

## ステップ9: 詰まったらフェイルオーバー
Claude Code が同じエラーを繰り返して進まない場合:

> “同じ失敗が3回続いたのでフェイルオーバーします。  
> Codexに渡すための引き継ぎパケット（再現手順・エラーログ・差分・期待結果）を作ってください。”

その後:
- GitHub PRで `@codex fix the CI failures` など（状況に合わせて）
