# instructions.md（運用ポリシー）

このファイルは、プロジェクト内での AI 自律駆動開発を「破綻しない」ための共通ポリシーです。

## [抽象化ルール]
- 具体名（Claude Code / Codex / Terminal など）は、必要に応じて以下のようにラベリングして一般化する
  - [AIコーディングエージェントA]=Claude Code
  - [AIコーディングエージェントB]=Codex
  - [コマンドライン実行環境]=ターミナル
  - [生成タスク]=実装・修正
  - [評価タスク]=レビュー・検証・テスト
  - [成果物]=コードベース
- ラベルは必ずブラケット `[]` で囲む

## [TDD原則]
- Red→Green→Refactor を最優先
- 変更は最小単位で、差分が説明可能であること
- テストが書けない場合は「設計が悪い」前提で分割・抽象化し直す

## [品質ゲート]
- CI と同等のコマンド（`scripts/ci/run_ci.sh` または `make ci`）が通るまで完了扱いにしない
- 依存追加・設定変更は必ず理由を記録する（`.ai/logs/`）

## [失敗時フェイルオーバー]
- 同一障害で 2 回以上詰まったら：
  1) 事実（ログ・再現）を整理
  2) 最小再現へ縮小
  3) [AIコーディングエージェントB] に引き継ぎ（/codex-takeover）


## [MiyabiFlow前提]（初心者・ターミナル中心）
- ユーザーは初心者。差分レビューを要求しない。
- ユーザーはターミナルでコマンド入力しない。代わりにAIが実行し、ユーザーは許可クリックだけ行う。
- スマホは GitHub コメントでの補助運用（@claude / @codex review）。
- 承認を求めるのは「技術スタック変更」「権限/コスト」「本番/移行」だけ（最大3つ）。
- 効率提案として、可能なら 3分割（統括/実装/検証）を推奨する。
